# Link Tracker

## О проекте

**Link Tracker** — это приложение для централизованного отслеживания обновлений контента на различных веб-ресурсах, таких как GitHub и StackOverflow. Вместо того чтобы проверять каждый сайт вручную, пользователи могут получать все уведомления в одном месте — через чат с ботом в Telegram.

Проект разработан в рамках курса "Академия Бэкенда".

### Проблема

Современному пользователю часто приходится следить за обновлениями на множестве сайтов. У каждого из них свой механизм оповещений (email, push, внутренние уведомления), что создает неудобства. Link Tracker решает эту проблему, предоставляя единый интерфейс для управления подписками и получения уведомлений.

## Сценарий использования

Взаимодействие с системой происходит через Telegram-бота. Основные шаги:

1.  **Регистрация**: Пользователь начинает диалог с ботом командой `/start`.
2.  **Управление подписками**:
    *   `/track` — добавить ссылку для отслеживания. Команда запускает диалог, в котором бот запрашивает URL и, опционально, теги.
    *   `/untrack` — прекратить отслеживание ссылки.
    *   `/list` — показать список всех отслеживаемых ссылок.
3.  **Получение уведомлений**: При появлении обновлений (например, новый ответ на StackOverflow или новый pull request на GitHub), бот автоматически присылает уведомление в чат.

## Архитектура

Приложение построено на микросервисной архитектуре и состоит из двух основных сервисов:

*   **Bot**: Сервис, отвечающий за взаимодействие с пользователем через Telegram API. Он обрабатывает команды, управляет состоянием диалогов и общается с сервисом Scrapper по REST API.
*   **Scrapper**: Сервис, который периодически проверяет отслеживаемые ссылки на наличие обновлений. При обнаружении изменений он отправляет уведомления в сервис Bot.

Взаимодействие между сервисами может осуществляться как синхронно (по HTTP), так и асинхронно (через Apache Kafka), в зависимости от конфигурации.

```
+-----------------+          +-------------------+
|                 |          |                   |
|  Telegram API   | <------->|        Bot        |
|                 |          |                   |
+-----------------+          +-------------------+
                                      ^
                                      |
                               HTTP / Kafka
                                      |
                                      v
+-----------------+          +-------------------+
|                 |          |                   |
|    PostgreSQL   | <------->|      Scrapper     |
|                 |          |                   |
+-----------------+          +-------------------+
                                      ^
                                      |
                                  API Calls
                                      |
                                      v
                          +------------------------+
                          | GitHub, StackOverflow  |
                          +------------------------+
```

## Технологический стек

- **Язык и фреймворк**: `Java 23`, `Spring Boot 3`
- **База данных**: `PostgreSQL`
- **Миграции**: `Liquibase`
- **Брокер сообщений**: `Apache Kafka` (опционально)
- **Кэширование**: `Redis` (опционально)
- **Сборка**: `Maven`
- **Тестирование**: `JUnit 5`, `Mockito`, `Testcontainers`
- **HTTP-клиент**: `Spring WebClient`

## Ключевые возможности

- **Отслеживание ссылок** с GitHub (репозитории) и StackOverflow (вопросы).
- **Диалоговый интерфейс** в Telegram для добавления ссылок.
- **Тегирование ссылок** для удобной организации.
- **Детализированные уведомления** с информацией об авторе, времени и превью контента.
- **Переключаемый транспорт уведомлений**: синхронный (HTTP) и асинхронный (Kafka).
- **Переключаемый слой доступа к данным**: `JDBC` или `JPA (Hibernate)`.
- **Обработка некорректных сообщений** в Kafka с использованием Dead Letter Queue (DLQ).
- **Кэширование** запросов в `Redis` для повышения производительности.

## Начало работы

### Требования
- JDK 23
- Docker и Docker Compose

### Сборка

Для сборки проекта и запуска тестов выполните команду в корневой директории:
```shell
./mvnw clean verify
```

### Запуск

Для локальной разработки и запуска всех необходимых сервисов (PostgreSQL, Kafka, Redis) используется `docker-compose`. Запустите его, а затем соберите и запустите модули `bot` и `scrapper` как обычные Spring Boot приложения.

### Конфигурация

Основные параметры приложения настраиваются в файле `application.yml`. Ключевые свойства:
- `app.telegram-bot-token`: Токен вашего Telegram-бота.
- `app.use-queue`: Включает использование Kafka для отправки обновлений (`true`/`false`).
- `app.database-access-type`: Определяет способ доступа к базе данных (`JDBC` или `JPA`).

Для дополнительной информации по командам сборки и разработки см. HELP.md.
